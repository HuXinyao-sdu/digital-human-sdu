## 1. 技术栈总览

| 层 | 选型 | 理由 |
|----|------|------|
| 语言 | Python 3.11（venv 隔离）+ Node.js 20+ | FastAPI生态成熟，前端Vite要求Node 18+ |
| 后端 | FastAPI + Uvicorn | 轻量async、自动API文档、适合Demo |
| 前端 | Vue 3 + Vite + Pinia + Vue Router + Axios | 上手快、生态成熟、3人团队易维护 |
| 3D渲染 | Three.js + Ready Player Me | 免费3D数字人形象、浏览器端实时渲染、无需GPU服务器 |
| 数字人视频生成 | EchoMimic V2（蚂蚁开源） | 一张照片+音频生成讲解视频，RTX 5070 Ti 16GB可跑 |
| 语音合成 | Edge-TTS（免费）→ GPT-SoVITS（音色克隆，进阶） | Edge-TTS零成本快速出活；GPT-SoVITS让声音更有特色 |
| 知识库 | RAG检索系统（已有，通过API接入） | 已有RAG问答系统，后端做转发层 |
| 老照片彩色化 | Stable Diffusion / DeOldify（已有成果） | 项目已有彩色化照片，扩充即可 |
| 部署 | Docker + Docker Compose + Nginx | 一键部署到GPU服务器 |
| 工程 | git + GitHub私有仓库 | 团队协作、版本管理 |

**离线AI生产流水线（服务器GPU）**：
```

             → EchoMimic V2生成讲解视频(.mp4)
             → 存入 data/generated-videos/
             → 后端通过 /api/content 返回给前端播放
```

## 3. 关键选型说明

### 3.1 数字人：双轨策略

| 模式 | 技术 | 用途 |
|------|------|------|
| **实时问答** | Ready Player Me 3D模型 + Three.js渲染 + 音频驱动唇形同步 | 用户自由提问，低延迟、可交互 |
| **主动讲解** | EchoMimic V2 预生成视频 | 按时间轴播放高质量讲解视频，口型准、表情自然 |

**为什么不用纯实时AI视频生成**：MuseTalk/LatentSync实时生成需要GPU服务器持续推理，延迟1-3秒，且长视频容易闪烁。预生成视频稳定可靠，实时3D渲染零延迟，两者互补。

### 3.2 RAG接入方式

已有RAG系统作为独立服务运行，后端FastAPI做**转发层**：
- 前端POST `/api/chat` → 后端 → 转发到已有RAG API → 返回答案
- RAG未配置时，后端返回关键词匹配的模拟回答（开发阶段）
- 切换只需改 `.env` 中的 `RAG_API_URL`，不改代码

### 3.3 3D数字人形象

用 [Ready Player Me](https://readyplayer.me) 免费生成：
- 在线拖拽创建"民国学者/讲解员"形象
- 导出GLB模型（自带ARKit表情 + Oculus唇形blendshape）
- 存入 `frontend/public/models/avatar.glb`
- 同时渲染一张正面高清PNG，作为EchoMimic的输入照片，保证两种模式形象一致

### 3.4 服务器GPU利用

RTX 5070 Ti 16GB 显存分配：
- **日常服务**：RAG转发（CPU为主）+ Edge-TTS（免费云API，不占GPU）→ 前端浏览器渲染3D，GPU空闲
- **离线批量生成**：EchoMimic V2（约8-10GB显存）批量生成讲解视频，挂后台overnight跑完
- **进阶**：GPT-SoVITS音色克隆（约4-6GB显存），训练一个专属讲解员音色
