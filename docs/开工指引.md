## 1. 通用标准（所有人必须遵守）

1. **接口合同是唯一语言**：所有模块的输入/输出用 `backend/app/models/` 里定义的 pydantic 类型。**改接口前先在群里说，改的是 schema，不是私下改签名。**
2. **边界**：每个人只改自己负责的目录/文件，不碰别人的。
3. **Git**：在自己负责的目录里改，commit 前先 `git pull`，commit 信息写清楚改了什么。
4. **提交信息**：`feat: 新功能` / `fix: 修复` / `data: 资料更新` / `docs: 文档`（中文描述）。
5. **验收标准**：每节末尾的"✅ 怎么算做完"，做完才算完。

## 2. 两大创新点（比赛核心亮点）

> 这两个是比赛答辩的记忆点，必须做出来。

### 创新点1：多数字人跨时空对话

**效果**：老舍和侯宝璋"面对面"聊天，讨论山大校史，有问有答、有互动。
- 两个数字人同框（或左右分屏）
- 一个人说话时另一个人做倾听表情
- 话题围绕校史，有自然的对话感

**技术实现**：
- 后端：对话脚本预写，按顺序播放两个数字人的视频片段
- 前端：两个3D模型并排，按脚本轮流激活
- 素材：EchoMimic分别生成老舍、侯宝璋的对话片段

### 创新点2：语音打断 + 多轮对话

**效果**：数字人正在讲解时，用户随时开口提问，数字人停下来回答；回答完继续讲。
- 技术：前端WebSocket实时检测语音 → 后端判断是否需要打断
- MVP版：讲解时显示"按住说话提问"按钮，松开即打断

## 3. A —— 内容与AI视频生产

### 3.1 本周任务：校史资料收集与整理

**第一步：收集资料（本周完成）**

| 资料类型 | 保存路径 | 需要多少 |
|----------|----------|----------|
| 历史事件 | `data/history/events/` | 至少10个核心事件 |
| 历史人物 | `data/history/figures/` | 至少5人（老舍、侯宝璋、杨振声、赵太侔、成仿吾） |
| 校园建筑 | `data/history/buildings/` | 至少3栋（齐鲁大学老建筑） |
| 老照片 | `data/photos/年代/` | 至少20张黑白照片 |

**第二步：整理为Markdown格式（本周完成）**

每个事件/人物/建筑一个 `.md` 文件，模板见 `docs/项目上手指南.md` 第三章。

- **✅ 验收**：`data/history/` 下至少有18个md文件，每个文件包含完整模板字段。

### 3.2 下周任务：讲解脚本 + 跨时空对话脚本 + AI视频

**讲解脚本**（第2-3周）：
1. 从校史资料中选6个主题，写口语化讲解脚本（每篇300-500字）
2. 保存到 `data/scripts/`，更新 `data/scripts/index.json`
3. 在服务器部署EchoMimic，批量生成讲解视频

**跨时空对话脚本（创新点1，第3周）**：
1. 写一段3-5分钟的"老舍×侯宝璋对话"脚本
2. 对话内容围绕：在山大的教学经历、对学生的印象、对医学/文学教育的看法
3. 格式：按对话轮次拆分，每轮标注是谁说的、说什么
4. 保存到 `data/scripts/dialogue-老舍-侯宝璋.md`
5. 用EchoMimic分别生成两人的对话视频片段

- **✅ 验收**：6段讲解视频 + 1段跨时空对话（左右分屏或同框）。

### 3.3 要学的工具最小集

| 工具 | 用途 | 学习成本 |
|------|------|----------|
| Markdown | 写资料和脚本 | 1小时 |
| Edge-TTS | 文字转语音 | 1小时 |
| EchoMimic | 照片+音频生成说话视频 | 2-3小时 |

**第一步：确认环境（今天）**
