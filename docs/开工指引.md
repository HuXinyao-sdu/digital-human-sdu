# 开工指引 V1（让历史动起来）

> 用途：告诉每个人"今天打开电脑，第一步做什么、按什么标准、怎么算做完"。
> 配套：团队分工与协作规范.md（分工总表）、技术路线.md（选型）、backend/app/models/（接口合同）

---

## 1. 通用标准（所有人必须遵守）

1. **接口合同是唯一语言**：前后端数据格式用 `backend/app/models/` 里定义的 pydantic 类型。**改接口前先在群里说，改的是 schema，不是私下改签名。**
2. **边界**：每个人只改自己负责的目录/文件，不碰别人的。
3. **Git**：在自己负责的目录里改，commit 前先 `git pull`，commit 信息写清楚改了什么。
4. **提交信息**：`feat: 新功能` / `fix: 修复` / `data: 资料更新` / `docs: 文档`（中文描述）。
5. **验收标准**：每节末尾的"✅ 怎么算做完"，做完才算完。

## 2. A —— 内容与AI视频生产

### 2.1 本周任务：校史资料收集与整理

**第一步：收集资料（本周完成）**

按照以下清单，从校史资料、《山东大学百年史》、网络资料中收集：

| 资料类型 | 保存路径 | 需要多少 |
|----------|----------|----------|
| 历史事件 | `data/history/events/` | 至少10个核心事件 |
| 历史人物 | `data/history/figures/` | 至少5人（老舍、侯宝璋、杨振声、赵太侔、成仿吾） |
| 校园建筑 | `data/history/buildings/` | 至少3栋（齐鲁大学老建筑） |
| 老照片 | `data/photos/年代/` | 至少20张黑白照片 |

**第二步：整理为Markdown格式（本周完成）**

每个事件/人物/建筑一个 `.md` 文件，模板见 `docs/项目上手指南.md` 第三章。

**文件命名规则**：
- 事件：`data/history/events/1901-山东大学堂创办.md`
- 人物：`data/history/figures/老舍.md`
- 建筑：`data/history/buildings/柏根楼.md`

- **✅ 验收**：`data/history/` 下至少有18个md文件，每个文件包含完整的模板字段（时间、背景、经过、意义）。

### 2.2 下周任务：讲解脚本撰写与AI视频生成

1. 从整理好的校史资料中，选取6个主题撰写口语化讲解脚本（每篇300-500字）
2. 脚本保存到 `data/scripts/`，更新 `data/scripts/index.json`
3. 在服务器上部署EchoMimic，用脚本+TTS音频批量生成讲解视频
4. 视频输出到 `data/generated-videos/`

- **✅ 验收**：6段讲解视频（每段1-2分钟），存入 `data/generated-videos/`，前端可通过API获取播放列表。

### 2.3 要学的工具最小集

| 工具 | 用途 | 学习成本 |
|------|------|----------|
| Markdown | 写资料和脚本 | 1小时 |
| Edge-TTS | 文字转语音（命令行） | 1小时 |
| EchoMimic | 照片+音频生成说话视频 | 2-3小时（跑通Demo） |

## 3. B —— 全栈开发与服务器运维

### 3.1 本周任务：接入RAG + 3D数字人 + 前后端联调

**第一步：确认环境（今天）**

```bash
# 后端环境
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# 前端环境（新开终端）
cd frontend
npm install
npm run dev
```

- **✅ 验收**：前端 http://localhost:5173 能打开，后端 http://localhost:8000/docs 能看到接口文档。

**第二步：接入已有RAG系统（本周内）**

1. 拿到已有RAG系统的API地址
2. 编辑 `backend/.env`，填写 `RAG_API_URL`
3. 测试：用Swagger UI发一个问题，确认RAG返回真实答案
4. 前端问答页能正常调用并展示

- **✅ 验收**：在前端问答页输入"老舍在山大做了什么"，返回的是RAG系统的真实回答，不是模拟回答。

**第三步：接入3D数字人模型（本周内）**

1. 在 https://readyplayer.me 生成数字人形象（参考C给的设计要求）
2. 导出GLB模型，URL加 `?morphTargets=ARKit,Oculus+Visemes`
3. 下载到 `frontend/public/models/avatar.glb`
4. 在 `frontend/src/views/Guide.vue` 中，用Three.js加载模型，替换当前的emoji占位
5. 实现：根据TTS音频音量驱动数字人嘴部动作（先做简单版）

- **✅ 验收**：Guide页面不再显示emoji，而是显示3D数字人模型；数字人在说话时嘴部有动作。

### 3.2 下周任务：TTS接口 + 双模式联动 + 题库嵌入

1. 后端增加 `/api/tts` 接口：文字→音频
2. 前端讲解模式：点击时间轴节点 → 播放AI讲解视频
3. 前端问答模式：用户提问 → RAG回答 → TTS播放 → 数字人嘴动
4. 嵌入题库网站（iframe）

- **✅ 验收**：两种模式可切换，问答有语音播放，题库页面可访问。

### 3.3 要学的技术最小集

| 技术 | 用途 | 学习成本 |
|------|------|----------|
| Vue 3 基础语法 | 写页面 | 已有基础即可 |
| Three.js 基础 | 加载和渲染3D模型 | 3-5小时 |
| FastAPI 路由 | 写新接口 | 已有基础即可 |
| Docker Compose | 一键部署 | 2小时 |
