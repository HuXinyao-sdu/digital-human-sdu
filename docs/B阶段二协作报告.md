## 需要全组确认的接口问题

### TTS 接口

当前实现：

```text
POST /api/tts
请求：{ "text": "..." }
响应：{ "audio_url": "/api/tts/audio/<filename>.mp3", "mime_type": "audio/mpeg" }
GET /api/tts/audio/{filename}
响应：MP3 音频文件
```

协作文档中写的是“POST 文字返回音频流”，与当前实现不同。请确认：

- 前端是否统一采用 `audio_url` 播放，还是改为直接返回二进制音频流；
- 是否加入 `voice` 参数，作为 MiniMax 音色选择；
- 音频缓存的保存期限和清理策略。

在群内确认前，请不要由其他成员改变 `/api/tts` 的请求或响应字段。

### RAG 问答接口

当前 `/api/chat` 仍是演示用关键词回答；RAG 服务尚未接入。需要 RAG 负责人确认：

- 服务地址与鉴权方式；
- 请求格式，例如 `{ question, session_id? }`；
- 响应格式，例如 `{ answer, sources? }`；
- 超时、失败和空检索结果的约定。

RAG 接入完成后，Guide 页现有的“回答文字 → TTS → 嘴型”流程无需重写，只需将回答来源切换为真实 RAG 结果。
