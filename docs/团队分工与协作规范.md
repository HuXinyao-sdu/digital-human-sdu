## 2. 三条铁律

1. **边界**：每个人只在自己负责的目录/文件里写，不碰别人的。
   - A：`data/history/`、`data/scripts/`、`data/photos/`、`data/generated-videos/`、`ai/scripts/`
   - B：`frontend/`、`backend/`、`deploy/`、`docker-compose.yml`
   - C：`data/avatar/`、`docs/`、前端UI设计对接
2. **合同**：前后端之间只通过API接口交互，不直接读对方内部文件格式。数据格式以 `backend/app/models/` 里的 pydantic 定义为准。
3. **改接口必须先商量**：谁要改接口（加字段、改字段名、改返回结构），先在群里说，确认后再改；绝不默默改签名导致对端报错。

## 4. Git 协作流程

- **仓库**：GitHub 私有仓库 https://github.com/HuXinyao-sdu/digital-human-sdu
- **分支**：`main`（稳定分支，所有人都往main提交，因为只有3人）
- **流程**：
  1. 每天开始前：`git pull`（拉最新代码）
  2. 改完代码：`git add .` → `git commit -m "描述"`
  3. 推送前：`git pull`（再次确认无冲突）
  4. 推送：`git push`
- **提交规范**：
  - `feat: 新功能描述`
  - `fix: 修复了什么问题`
  - `data: 添加了什么资料`
  - `docs: 更新了什么文档`
  - `refactor: 重构了什么`
- **不提交的文件**（已在 `.gitignore` 中排除）：
  - `node_modules/`、`venv/`、`__pycache__/`
  - `.env`（本地配置）
  - `ai/weights/`（模型权重，几十GB）
  - `.idea/`、`.vscode/`（编辑器配置）
  - 大视频文件用 Git LFS 管理

## 5. 代码规范

- **Python**：函数写docstring，类型标注，变量名用英文snake_case
- **前端**：组件名用PascalCase（如 `GuidePage.vue`），变量用camelCase
- **Markdown资料**：统一UTF-8编码，标题层级清晰（# 一级标题，## 二级标题）
- **JSON文件**：缩进2个空格，最后一个key不加逗号

**新增接口的流程**：
1. B在 `backend/app/models/` 中定义请求/响应schema
2. 在群里通知A和C接口格式
3. B实现后端路由
4. B在 `frontend/src/api/index.js` 中添加前端调用函数
5. A/C在各自页面中调用

## 7. 数据文件格式约定

后端读取的数据文件统一放在 `data/` 目录：

### 7.1 校史资料（Markdown）
- 事件：`data/history/events/年份-事件名.md`
- 人物：`data/history/figures/姓名.md`
- 建筑：`data/history/buildings/建筑名.md`

### 7.2 JSON索引
每个数据目录下有一个 `index.json` 或 `manifest.json`：
```json
{
  "version": "0.1.0",
  "updated_at": "2026-09-18",
  "items": [
    {"id": 1, "title": "...", "era": "1901", "file": "events/xxx.md"}
  ]
}
```

### 7.3 照片和视频
- 照片：`data/photos/年代/文件名.jpg`，登记在 `manifest.json`
- 视频：`data/generated-videos/编号-标题.mp4`，登记在 `manifest.json`
