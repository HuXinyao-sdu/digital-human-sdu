## 一、项目是什么

### 1.1 项目简介

本项目是山东大学人工智能学院院级立项项目，聚焦**山东大学趵突泉校区百年校史**，通过AI技术打造可交互、可对话的校史讲解平台。

**核心功能**：
- 🎙️ AI数字人实时讲解校史故事
- 🖼️ 老照片AI彩色修复与动态化
- 📅 校史时间轴漫游
- 💬 RAG智能问答（提问即答）
- 📚 题库测试

### 1.2 技术栈

| 模块 | 技术 | 说明 |
|------|------|------|
| 前端 | Vue 3 + Vite + Vue Router + Pinia + Axios + Three.js | 网页界面、3D数字人渲染 |
| 后端 | FastAPI + Uvicorn + Pydantic | RESTful API、业务逻辑 |
| 数字人 | Ready Player Me (3D模型) / EchoMimic (AI视频生成) | 实时交互/预生成讲解视频 |
| 语音 | Edge-TTS / GPT-SoVITS | 文字转语音 |
| 知识库 | RAG检索增强生成（已有系统） | 问答大脑 |
| 部署 | Docker + Docker Compose + Nginx | 一键部署 |

### 1.3 服务器

- **GPU服务器**：RTX 5070 Ti 16GB，Ubuntu 26.04，用于AI模型推理和视频生成
- **Web服务**：前端Nginx + 后端FastAPI

## 四、成员分工与文件职责

### 4.1 成员A：内容与AI视频生产

**负责的文件夹**：
```
ai/scripts/               # AI生成脚本
data/history/             # 校史资料整理（与资料同学对接）
data/scripts/             # 讲解脚本成品
data/photos/              # 老照片彩色化
data/generated-videos/   # AI生成的讲解视频
```

**负责的文件与功能**：

| 文件/目录 | 功能 | 产出 |
|-----------|------|------|
| `ai/scripts/batch_generate.py` | 批量生成数字人讲解视频 | 12-15段讲解视频 |
| `ai/scripts/tts_single.py` | 单条TTS语音合成 | 讲解音频 |
| `ai/scripts/video_postprocess.py` | 视频后处理（字幕、压缩） | 成品视频 |
| `data/history/*.md` | 校史资料整理（事件/人物/建筑） | 50+篇资料 |
| `data/scripts/*.md` | 数字人讲解脚本（口语化成品稿） | 12-15篇脚本 |
| `data/photos/` | 老照片彩色化成果 | 30+张彩色照片 |

**对接关系**：
- 从资料同学处接收原始资料 → 整理为Markdown
- 将整理好的资料写入 `data/history/` 和 `data/scripts/`
- 将彩色化照片放入 `data/photos/`
- 后端从 `data/` 读取数据 → 通过API返回给前端

**效果展示**：
- 数字人讲解页：点击主题后播放对应的AI生成讲解视频
- 图库页：展示彩色化后的老照片，可对比原图
- 问答：讲解内容与RAG知识库一致

## 五、代码接口与协作约定

### 5.1 前后端接口约定

前端所有请求都通过 `frontend/src/api/index.js` 封装，后端接口统一以 `/api` 开头。

#### 现有接口

| 接口 | 方法 | 请求参数 | 返回格式 | 说明 |
|------|------|----------|----------|------|
| `/api/health` | GET | 无 | `{status, version}` | 健康检查 |
| `/api/chat` | POST | `{question: string, session_id?: string}` | `{answer, sources, session_id}` | 问答交互 |
| `/api/content/scripts` | GET | 无 | `{total, items: [{id, title, era, duration}]}` | 讲解脚本列表 |
| `/api/content/gallery` | GET | 无 | `{total, items: [{id, title, era, location, image_url}]}` | 图库列表 |

#### 前后端联调流程

```
前端（成员B）                          后端（成员B）
    │                                      │
    │  1. 在 frontend/src/api/index.js     │
    │     定义接口请求函数                  │
    │                                      │
    │  2. 在页面组件中调用                  │
    │     const res = await chat(...)      │
    │                                      │
    │ ────────── HTTP POST /api/chat ────> │
    │                                      │ 3. 后端收到请求
    │                                      │    调用RAG/TTS/读文件
    │                                      │
    │ <────── JSON {answer: "..."} ────── │
    │                                      │
    │  4. 前端渲染返回结果                  │
```

#### 新增接口的协作约定

1. **后端先定义接口**：在 `backend/app/api/` 新建文件，定义路由和数据模型
2. **同步更新文档**：在 `backend/app/models/response.py` 中定义返回格式
3. **前端对接**：在 `frontend/src/api/index.js` 中添加对应请求函数
4. **字段命名**：统一用英文snake_case（如 `session_id`、`image_url`）
5. **错误处理**：后端返回HTTP状态码，前端统一在 `api/index.js` 的拦截器中处理

### 5.2 数据文件格式约定

后端读取的所有数据文件统一放 `data/` 目录，格式为JSON或Markdown：

```
data/
├── history/
│   └── index.json          # 校史资料总索引
├── scripts/
│   └── index.json          # 讲解脚本索引
├── photos/
│   └── manifest.json       # 照片清单
└── generated-videos/
    └── manifest.json       # 生成视频清单
```

**JSON索引文件格式**：

```json
{
  "version": "0.1.0",
  "updated_at": "2026-09-18",
  "items": [
    {
      "id": 1,
      "title": "山东大学堂创办",
      "era": "1901",
      "year": 1901,
      "file": "events/1901-山东大学堂创办.md",
      "summary": "1901年袁世凯上奏创办山东大学堂"
    }
  ]
}
```

## 七、Git提交与协作流程

### 7.1 日常开发流程

每次修改代码后，按以下步骤提交：

```bash
# 1. 先拉取最新代码（避免冲突）
git pull

# 2. 查看修改了哪些文件
git status

# 3. 添加修改的文件（用.添加全部，或指定文件名）
git add .
# 或 git add frontend/src/views/Home.vue

# 4. 提交（写清楚改了什么）
git commit -m "feat: 描述你做了什么修改"

# 5. 推送到GitHub
git push
```

### 7.2 分支策略

**默认在 `main` 分支开发**（项目小，不需要复杂分支）。

如果要开发大功能，建议新建分支：
```bash
# 新建并切换到功能分支
git checkout -b feature/digital-human-3d

# 开发完成后提交
git add .
git commit -m "feat: 接入3D数字人模型"
git push -u origin feature/digital-human-3d

# 在GitHub上发起Pull Request，合并到main
```

### 7.3 常见情况处理

#### 情况1：push失败，提示远程有新提交

```bash
# 先拉取并合并
git pull

# 如果有冲突，手动编辑冲突文件后：
git add .
git commit
git push
```

#### 情况2：提交信息写错了

```bash
# 还没push时
git commit --amend -m "新的提交信息"

# 已经push了（不推荐，但可用）
git commit --amend
git push -f
```

#### 情况3：想撤销上一次提交但保留修改

```bash
git reset --soft HEAD~1
```

#### 情况4：不想提交某些文件

把文件名加到 `.gitignore`：
```
# 在 .gitignore 中添加
backend/.env
__pycache__/
node_modules/
```

### 7.4 不应该提交的文件

以下文件**不要提交到GitHub**（已在 `.gitignore` 中排除）：

| 文件/目录 | 原因 |
|-----------|------|
| `node_modules/` | 前端依赖，可通过npm install重新生成，体积巨大 |
| `__pycache__/`、`*.pyc` | Python缓存 |
| `venv/` | Python虚拟环境 |
| `.env` | 本地环境变量，含敏感信息 |
| `ai/weights/` | AI模型权重，几十GB |
| `.idea/`、`.vscode/` | 编辑器配置 |
| `dist/`、`build/` | 构建产物 |

## 九、常见问题

### Q1：后端启动报错 `ModuleNotFoundError: No module named 'fastapi'`

**原因**：没激活虚拟环境，或没安装依赖。

**解决**：
```bash
cd backend
venv\Scripts\activate
pip install -r requirements.txt
```

### Q2：前端启动报错 `Cannot find module 'vue'`

**原因**：没装npm依赖。

**解决**：
```bash
cd frontend
npm install
```

### Q3：前端页面能打开，但问答功能不工作

**检查清单**：
1. 后端是否在运行？（访问 http://localhost:8000/api/health 看是否返回ok）
2. 浏览器F12 → Console有没有报错？
3. 浏览器F12 → Network看 `/api/chat` 请求是否发出去了？返回什么？

### Q4：git push提示权限错误

**原因**：没有GitHub仓库权限，或没登录。

**解决**：
1. 确认你已经被加为仓库协作者（联系成员B）
2. push时弹出浏览器登录窗口，用GitHub账号授权
3. 或配置Personal Access Token作为密码

### Q5：端口被占用

**后端端口被占**：换个端口启动：
```bash
uvicorn app.main:app --reload --port 8001
```

**前端端口被占**：Vite会自动用下一个端口（5174），不用管。

### Q6：怎么把新收集的资料提交上去

1. 把资料文件放到 `data/` 对应目录
2. 如果是照片，更新 `data/photos/manifest.json`
3. 提交：
```bash
git add data/
git commit -m "data: 添加老舍人物资料和老照片"
git push
```
